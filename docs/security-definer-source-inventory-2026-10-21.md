# `SECURITY DEFINER` lähtekoodi inventuur — 21.10.2026

## Kokkuvõte

Ülevaatus on ainult hoidla `main` lähtekoodist commit'il `daa8bdc` (21.10.2026). Tootmisandmebaasi, Supabase'i katalooge ega seadeid ei loetud. Seetõttu kirjeldab tabel migratsioonides nähtavat kavandatud lõppseisu, mitte tootmise tegelikke `pg_proc.proacl` õigusi.

Leidsin 15 `public`-skeemi `SECURITY DEFINER` funktsiooni, millele migratsioonid annavad `authenticated` rollile `EXECUTE`, ning kaks samas rollis täidetavat `hunt_private` teostusfunktsiooni. Lisaks on kaks triggeri funktsiooni ja üks Auth hook `SECURITY DEFINER`, kuid neid ei anta `authenticated` RPC-na täita. Sisselogimispiiraja hilisem lõppversioon on `SECURITY INVOKER` ja ainult `service_role` jaoks. Loend arvestab sama funktsiooni ümberdefineerimised üheks ning kasutab viimast migratsiooni definitsiooni.

15.10.2026 turvaülevaatus märkis 15 `authenticated SECURITY DEFINER` turvanõustaja hoiatust, kuid ei loetlenud neid funktsioonide kaupa ning rõhutas, et hoiatus ei tõenda iseenesest nõrkust. Praeguse `main` allikakoodis kattub 15 avaliku RPC inventuur selle hoiatuste arvuga; lisaks on kaks `hunt_private` funktsiooni. Tootmise turvanõustaja tulemust ega tegelikku funktsioonide ACL-i siin ei kontrollitud.

## Prioriteetsed järelkontrollid

1. **P1 — kontrolli testprojektis lõplikku funktsioonide ACL-i kataloogist.** Lähtekoodis on sihitud `REVOKE`/`GRANT` migratsioonid nähtavad, kuid testid ei tee kõigi 15 avaliku ja 2 privaatse funktsiooni kohta `has_function_privilege` / `pg_proc.proacl` maatriksit. Lisa eraldi ajutises testprojektis kontroll `anon`, `authenticated` ja `service_role` rollidele; võrdle iga tulemuse `EXECUTE` õigust tabelis oleva kavatsusega. See on kontrolli katvuse puudujääk, mitte tõend üleliigsest õigusest.
2. **P2 — lisa sihitud test `hunt_member_choices()` nähtavusele.** Kood lubab iga aktiivse liikmelisusega kontol kutsuda RPC-d ja loetleda aktiivsete kasutajate nimed. Kontrolli omaniku, admini, liikme ja vaataja ootuspärast tulemust ning kinnita, kas see on soovitud käitumine.
3. **P2 — täienda funktsioonispetsiifilisi regressiooniteste.** Eriti `set_viewer_layers` mitteadmin/owner rollid, `member_name` mitteaktiivse/välise kasutaja vastus, triggeri `protect_hunt_update` piirangud ning `hunt_private` skeemi API eksponeeritus. Olemasolev PGlite test-fixture ei ole sama, mis tootmise Supabase API konfiguratsioon.
4. **P3 — jätka teadlikku `SECURITY DEFINER` haldust.** Sisemine funktsioonide skeem võib olla järgmise kavandatud andmebaasirefaktori teema, nagu 15.10 audit märgib. Ära eemalda õigustatud RLS-i abifunktsioone pelgalt turvanõustaja hoiatuse tõttu; säilita fikseeritud `search_path`, minimaalsed grant'id ja rollipõhised testid.

## Piirangud

- Ainult lähtekoodi lugemine; tootmisandmebaasi ega kasutajaandmeid ei kasutatud.
- Migratsioonide järjekord ja hilisemad `CREATE OR REPLACE` / `REVOKE` muudavad varasemate failide definitsioone. Tabel kajastab viimast tuvastatud lähtekoodi kavatsust; see ei kinnita migratsioonide tootmises rakendamist ega tegelikku ACL-i.
- `hunt_private` skeemi eksponeeritud/REST-is lubatud nimekiri on projekti seadistus ega kajastu repo lähtekoodis; seetõttu on API kaudu otsekutsumine kontrollimata.
- Testide olemasolu ja koodis nähtavus ei võrdu nende käivitamisega selles ülevaatuses. Ühtegi testi ega tootmispäringut ei käivitatud.
